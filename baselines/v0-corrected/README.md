# v0-corrected baseline bundle

Corrected baseline for the v0 stock-selection protocol. This bundle is
`baselines/v0-legacy/` plus exactly one hunk: the record block of `code/ga.py` moved so the
generation best is recorded from the population it belongs to (the canonical
`(old_bytes, new_bytes)` transform of spec.md, proven byte-equal in
`tests/test_v0_corrected_bundle.py`). Everything else - code, data, protocol - is byte- or
AST-equal to the frozen archive. The results in `reference/` were generated by the frozen
writer in the declared environment and every row's reported `fitness` re-derives from that
row's own returned chromosome (120/120 rows, `verify_artifacts.py`).

## What is here

| Path | What it is |
| --- | --- |
| `code/` | the frozen modules the run executes; `ga.py` carries the one corrected hunk |
| `data/processed/` | byte-identical copies of the frozen data the protocol ranks |
| `reference/` | the corrected results (4 per-profile run CSVs, the multi-run summary, 4 consensus files) - generated, never hand-edited |
| `protocol.json` | the v0-legacy protocol deep-equal plus `baseline_id`/`derived_from` |
| `baseline.json` | the manifest pinning `code/`, `data/`, `reference/` (sha256 + git blob sha1 per file) |
| `status.json` | the verdict map over the affected legacy artifacts (see the note below) |
| `environment.txt`, `requirements.txt` | the declared generating environment and its caveat |
| `tools/` | the manifest tools, the frozen recomputation, the artifact verifier, the reference generator |

## Methodological note: what the P0-02 capture defect invalidates

The legacy capture (`py/ga.py:115,129,132-135`, frozen as `baselines/v0-legacy/code/ga.py`)
records each generation's best fitness against the replaced population, so a recorded fitness
belongs to a different portfolio than the one returned. This note bounds what that defect
invalidates. Each statement below is checked verbatim by substring tests in
`tests/test_v0_corrected_status.py`.

### Invalidation scope

- reported fitness is invalid wherever the legacy capture recorded a generation best
- portfolio-return interpretation is unchanged and returns/tickers/hhi stand on their own measured self-consistency
- rows whose recorded score fields do not reproduce from the frozen snapshot under the declared weights are marked `score_provenance_inconsistent` and rows whose producer or chromosome cannot be reconstructed are marked `not_verifiable_at_head` - neither is attributed to the capture defect
- no blanket invalidation of historical backtests is presumed

`baselines/v0-corrected/status.json` is the verdict map: one entry per recorded value, with
its evidence fields (`producer`, `row_reconstruction`, `score_recompute`,
`data_snapshot_match`, `reported`, `recomputed`) and the verdict computed from them by the
Verdict Attribution Rule. A defect reference is recorded only on the verdicts the rule
attributes to the capture defect; every other non-`valid` verdict carries its own reason.

### Reproducibility limits

- archived v0-legacy values are not reachable in the declared environment where measured (caio run 0 replays to fitness 6.244563 - legacy and corrected agree - with hhi 0.16 from the legacy driver against the archived 4.604746 with hhi 0.26, the corrected driver's hhi for that run being 0.18)
- the production `outputs/carteira_caio_consensus.json` was produced by the corrected optimizer over a 150-run set the archive does not contain (its FREQUENCY values are exact counts over 150: 38, 34, 33, 25, 22, 21, 21, 20, 20, 17, and its sibling `outputs/metrics_stability_caio.csv` carries `generations_run`/`converged_early`) while the archived consensus came from the defective capture - so the membership difference is a provenance difference, not evidence that the live recommendation is defective
- the archive's `fitness` column is bit-identical to the corrected reference for 78 of 90 control-profile rows, the other 12 differing by at most 2 ULP (4.3e-16 relative) because the archive's generating environment is unrecorded, while legacy and corrected report bit-identical fitness on 80 of 80 replay runs in the declared environment (the committed proof `proofs/replay_20seeds.json`, seeds 42-61) and the corrected reference ties to the corrected driver row-by-row on 120 of 120 rows (`generation_proof.json`) - the 120-row both-driver observation was an ad-hoc measurement and is not a committed artifact
- no reproducibility claim is made beyond the committed proofs

Measured precision on the third limit: every one of those 12 rows drifts by 1-2 ULP and the
maximum relative difference is 4.3e-16
(`.specs/features/p0-02-v0-corrected/proofs/control_ulp_drift.json`).
The comparison of record is `proofs/replay_20seeds.json`, the opt-in 20-seed x 4-profile
both-driver replay committed under `.specs/features/p0-02-v0-corrected/proofs/`. The
environment those proofs
need is declared in `environment.txt` with its wheels caveat; that environment is not
durable, and this note makes no claim beyond the committed proofs.
